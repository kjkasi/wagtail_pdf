# План: Bootstrap, модальный PDF и поддержка целевых браузеров

Дата: 2026-09-27. Статус: запланировано, реализация не начата.
Заменяет требования к публичной раскладке из `PDF_VIEWER_CHANGE_PLAN.md`.
Исправление совместимости заблокировано до воспроизведения и подтверждения причины (этап 0). Bootstrap не является исправлением несовместимости PDF.js.

## 1. Согласованные требования

- Перевести **весь публичный сайт** на Bootstrap: главную, каталог, страницу документа, общий каркас и оформление страниц ошибок. Штатную админку Wagtail не переписывать.
- Целевые пакеты ALT Linux, сообщённые пользователем:
  - `firefox-esr`, версия `140.14.0-alt1`;
  - `yandex-browser-stable`, версия `25.2.4.1000-alt1`.
- Это два отдельных целевых браузера: Яндекс Браузер не обозначаем как Firefox ESR. Номера движков и ОС фиксируем по фактической установке, не выводим из имени пакета.
- При входе на страницу документа PDF **автоматически открывается в модальном окне**. После закрытия остаются описание, ссылка в каталог и кнопка повторного открытия.
- На физическом экране **1920×1080** целая текущая PDF-страница и все кнопки помещаются в видимую область при начальном масштабе. Не требуется полноэкранный режим браузера.
- По умолчанию масштаб «Вписать страницу» по ширине **и высоте**. При увеличении прокручивается только область PDF, а кнопки остаются видимыми.
- Сохранить навигацию, устойчивость к быстрым нажатиям, zoom, встроенные аннотации, внутренние и безопасные внешние ссылки, сообщения об ошибках.

## 2. Что установлено по коду, а что ещё не доказано

### Подтверждённые ограничения

- Используется `pdfjs-dist 6.3.289`. Vendor-скрипт копирует стандартные `build/pdf.mjs` и worker, а не legacy-сборку.
- PDF.js импортируется статически. Ошибка разбора/импорта зависимости может произойти **до** обработчика ошибки загрузки документа и оставить сообщение «Загрузка PDF…».
- Масштаб вычисляется только по ширине stage. Высота PDF не ограничивается доступной высотой экрана.
- Высота viewer равна почти целому viewport, но над ним остаются шапка сайта и заголовок документа. Дополнительно установлена минимальная высота. Поэтому нахождение toolbar в пределах экрана не гарантировано.
- Браузерный тест запускает только Playwright Chromium. Он не доказывает работу указанных пакетов Firefox/Яндекс.
- Проверка `to_be_visible()` не доказывает полное вхождение PDF и кнопок в viewport; автоматический click может сам прокрутить страницу.

### Диагностический статус

Пользователь повторно подтвердил сбой и связал его с браузерами. Конкретное исключение, отсутствующий API или несовместимый синтаксис пока не получены. Нельзя объявлять PDF.js 6.3.289 несовместимым именно с указанными версиями без воспроизведения.

Это продолжение незакрытой браузерной/LAN-проверки предыдущего плана, не повтор ошибки Wagtail inline-валидации.
Security impact: NONE по имеющимся данным; путь эксплуатации не выявлен. Существующие ограничения PDF scripting и ссылок сохранить.

## 3. Целевая архитектура

### Bootstrap

- Использовать Bootstrap 5.3.x; точный patch закрепить в `package.json` и lock-файле после проверки документации и целевых браузеров.
- Поставлять CSS и JS локально через Django static, без CDN и внешних сетевых зависимостей. Копировать лицензии. `npm run build:vendor` должен собирать Bootstrap и PDF.js воспроизводимо.
- Заменить самописные сетки, карточки, кнопки и общие компоненты средствами Bootstrap (`container`, grid, cards, buttons, alerts, modal).
- Оставить только необходимый CSS для PDF-stage, слоёв аннотаций, ограничения высоты и небольших визуальных настроек. Не переписывать официальный annotation CSS вручную.
- Проверить каскад Bootstrap/Reboot и PDF.js, focus и stacking Wagtail userbar. Удалить устаревшие стили и текст «PDF + комментарии» на главной.

### Модальное окно

- Один Bootstrap modal на странице документа, предпочтительно `modal-fullscreen`: максимум доступного места, не Fullscreen API.
- Компактный header с названием и кнопкой закрытия; растягиваемый stage; отдельная панель управления без наложения поверх PDF.
- Автоматический показ после готовности DOM/Bootstrap. Измерение stage и первый render только после `shown.bs.modal` — скрытое окно имеет неверные размеры.
- Высота ограничена фактической высотой viewport. Для flex-областей использовать `min-height: 0`/`min-width: 0`; убрать прежние фиксированные minimum-height. Предусмотреть `vh` fallback, не полагаться только на `dvh`.
- На закрытии остановить/инвалидировать текущий render; не коммитить устаревший результат в скрытое окно. Повторное открытие сохраняет текущую страницу и пользовательский zoom, пересчитывает доступный размер и не добавляет повторные обработчики/worker.
- Закрытие крестиком и Escape; фокус ограничен modal и после закрытия возвращается к кнопке «Открыть PDF» (важно при автоматическом показе без исходного trigger).
- Длинный заголовок не вытесняет кнопки и stage: ограничить отображаемую высоту, сохранить полное доступное название.

### Геометрия и масштаб

Измерять stage после раскладки header/toolbar. Вычесть реальные padding и границы, а не постоянные 32 px:

```text
availableWidth  = ширина внутренней области stage
availableHeight = высота внутренней области stage
fitScale = min(availableWidth / pageWidth, availableHeight / pageHeight)
effectiveScale = fitScale * zoomFactor
```

- При `zoomFactor = 1` целая страница помещается без прокрутки; надпись «100%» означает 100% от масштаба вписывания, не физический размер PDF.
- Сохранить диапазон 50–300%, шаг 25%; заменить «По ширине» на «Вписать страницу».
- При смене ориентации страницы пересчитывать fitScale; пользовательский множитель сохранять.
- После zoom > 100% разрешить прокрутку внутри stage, включая доступ к левому/верхнему краю увеличенной страницы. Toolbar/header не прокручивать вместе с PDF.
- Один viewport для canvas и annotation layer; DPR влияет на качество растра, не на CSS-размер.
- Resize скрытого окна не запускает рендер с нулевой геометрией. После открытия размер измеряется заново.

## 4. Порядок работ и проверки

Каждый шаг выполнять отдельным вертикальным циклом RED → GREEN, не переписывать всё одним коммитом.

### Этап 0. Воспроизвести браузерный сбой — обязательный gate

1. На проблемном ALT-компьютере зафиксировать версию ОС, пакетов, браузеров, User-Agent/движок, масштаб браузера и дисплея, `innerWidth/innerHeight`, URL и используемый PDF.
2. Открыть старый viewer по фактическому LAN HTTP-адресу. Сохранить Console, HAR и скриншот; перед сохранением удалить cookies, токены и чувствительные параметры.
3. Отдельно проверить загрузку viewer-модуля, PDF.js, worker, CSS, изображений аннотаций и PDF: HTTP status, MIME и исключения.
4. Изолировать сбой: импорт библиотеки → запуск worker → открытие PDF → canvas → annotation layer. Проверить тот же PDF и URL в обоих целевых браузерах.
5. Проверить гипотезы по отдельности: неподдерживаемый синтаксис/API; worker; сетевые/MIME ошибки; annotation API/CSS. Для каждой сохранить результат проверки, а не предположение.
6. Подтвердить первопричину минимальным воспроизведением. Только после этого выбрать изменение сборки/загрузки PDF.js.

**Gate:** нет доступа к точным браузерам или нет воспроизведения — совместимость остаётся `blocked`, а не `verified`. Работы над согласованным интерфейсом можно вести независимо, но закрывать баг нельзя.

### Этап 1. Локальные Bootstrap-ресурсы и публичные страницы

**RED:** тесты главной, каталога (пустого и заполненного), страницы документа и ошибок проверяют доступность контента/навигации, локальные CSS/JS и отсутствие CDN.

**GREEN:** закрепить Bootstrap, расширить vendor build, обновить базовый и публичные шаблоны, убрать дублирующий CSS. Сохранить Django/Wagtail URL, фильтрацию черновиков и семантику ссылок.

**Проверка:** `npm run build:vendor`; `.venv/Scripts/python.exe -m pytest catalog/tests/test_pages.py -q`.

### Этап 2. Жизненный цикл modal

**RED:** переход по URL документа автоматически открывает modal и PDF; закрытие/Escape возвращают к описанию и кнопке открытия; повторное открытие работает; focus не уходит за modal. Закрытие во время загрузки/рендера не создаёт ошибок или устаревшего изображения.

**GREEN:** добавить modal-разметку и управление Bootstrap-событиями; инициализировать viewer по видимому stage; сделать повторное открытие идемпотентным, защитить асинхронные результаты счётчиком поколения/отменой.

**Проверка:** `.venv/Scripts/python.exe -m pytest catalog/tests/test_pages.py catalog/tests/test_browser.py -q`.

### Этап 3. Целая страница и кнопки в viewport

**RED:** unit-тест расчёта fitScale для книжной/альбомной страницы и ограничений по обеим осям; browser-тест проверяет полные bounding boxes страницы и каждой кнопки внутри viewport до любых кликов. Проверить смену ориентации, длинный заголовок, resize, zoom и возврат к fit.

**GREEN:** новая ограниченная высотой modal раскладка и вычисление fitScale по двум осям; прокрутка только stage при увеличении. Сохранить очередь рендера и синхронность слоёв.

**Проверка:** `npm run test:js`; `.venv/Scripts/python.exe -m pytest catalog/tests/test_browser.py -q`.

### Этап 4. Исправить подтверждённую причину несовместимости

Начинать **только после gate этапа 0**. Точная реализация пока не выбрана.

**RED:** воспроизводимый сценарий в целевом браузере показывает подтверждённый сбой; отдельно тестируются отказ импорта PDF.js, worker и PDF, чтобы загрузка не зависала без сообщения.

**GREEN:** выбрать минимальное подтверждённое исправление. Возможные варианты для проверки, не готовый диагноз: совместимая legacy-сборка той же версии PDF.js; необходимые точечные polyfill; устранение конкретной ошибки worker/MIME. Legacy не гарантирует поддержку любых старых браузеров. Не откатывать библиотеку на устаревшую небезопасную версию без анализа.

Основной модуль, worker, annotation CSS и ресурсы должны быть согласованы по версии. Проверить синтаксис и API собственного JS. Предусмотреть совместимый стартовый загрузчик с обработкой ошибок импорта; сообщение для невозможности запуска, а не бесконечный loader. Не ослаблять CSP/CORS/политику ссылок ради обхода ошибки.

**Проверка:** vendor build, JS-тесты, browser suite и повтор первоначального сценария в обоих **точных ALT-пакетах** с сохранением доказательств.

### Этап 5. Регрессии и итоговая приёмка

- Playwright Chromium и Firefox использовать как быстрый автоматический gate. Playwright Firefox не равен Firefox ESR, Chromium не равен Яндекс Браузеру.
- Реальные ALT-пакеты проверять на целевой машине/VM. Для автоматизации использовать только подтверждённо совместимый runner; иначе обязателен ручной протокол.
- Сохранить результаты отдельно для каждого браузера: версии, разрешение экрана, viewport, scaling, URL, PDF, сценарий, результат, Console/HAR/скриншоты.
- Обновить README: список поддерживаемых версий, локальная сборка, modal/fit/zoom и LAN-проверка. Не объявлять поддержку всех ESR без определённой матрицы.

Команды общего gate в текущем Windows-окружении:

```bash
npm ci
npm run build:vendor
npm run test:js
.venv/Scripts/python.exe manage.py check
.venv/Scripts/python.exe manage.py makemigrations --check --dry-run
.venv/Scripts/python.exe -m pytest -q
```

На ALT использовать python из соответствующего venv. Новые тесты сначала должны показать ожидаемое падение, затем пройти после соответствующего изменения.

## 5. Матрица и критерии приёмки

- [ ] Firefox ESR `140.14.0-alt1`: PDF, worker, canvas и аннотации работают по LAN URL.
- [ ] Яндекс Браузер `25.2.4.1000-alt1`: тот же сценарий работает.
- [ ] Bootstrap-ресурсы локальны; главная, каталог, документ и страницы ошибок оформлены согласованно; админка не изменена.
- [ ] Modal открывается автоматически; крестик/Escape/повторное открытие работают; focus доступен с клавиатуры.
- [ ] На физическом экране 1920×1080 при обычном максимизированном окне (не F11), zoom браузера 100%, зафиксированном системном scaling целая страница и все кнопки видимы без прокрутки.
- [ ] Автотест отдельно проверяет viewport 1920×1080, 1920×900 (запас под панели браузера/ОС), 1280×720 и mobile 390×844. Размер физического экрана не приравнивается к CSS viewport.
- [ ] Для каждой кнопки, canvas и toolbar: `x >= 0`, `y >= 0`, `right <= innerWidth`, `bottom <= innerHeight` с допуском округления 1 px. В режиме fit stage не имеет переполнения более 1 px. Проверка выполняется без scroll-into-view.
- [ ] В fit книжные и альбомные страницы помещаются целиком; после zoom прокручивается только stage, края PDF достижимы.
- [ ] Навигация, быстрые повторные нажатия, resize и закрытие при рендере не показывают устаревшую страницу; toolbar не прыгает при смене ориентации.
- [ ] Canvas и аннотации совмещены после fit/zoom/resize; заметки/выделения/ссылки сохранены; PDF scripting отключён, внешние ссылки безопасны.
- [ ] Ошибки импорта, worker и загрузки PDF показывают понятное сообщение; окно можно закрыть даже при отказе viewer.
- [ ] Все тесты проходят; в успешных сценариях отсутствуют необработанные JS-ошибки и отказы обязательных ресурсов.
- [ ] Изначальный сбой воспроизведён до исправления и отсутствует после него в каждом целевом браузере. Без этого баг не закрывать.

## 6. Границы и риски

Модели, миграции, данные PDF, публикация и валидация Wagtail не меняются. Не возвращать удалённые редакторские комментарии. Поиск, печать, thumbnails и редактирование PDF вне объёма.

Основные риски: несовпадение движков тестового и целевого браузеров; конфликт Bootstrap/PDF.js CSS; измерение скрытого modal; гонки при закрытии; toolbar вне viewport; несогласованные vendor-версии. Снижение риска: точная браузерная матрица, первый render после показа, единая геометрия слоёв, проверки реальных координат, тесты lifecycle и локальная воспроизводимая сборка.

Рекомендуемые отдельные коммиты: Bootstrap-каркас → modal lifecycle → fit-page/геометрия → подтверждённое исправление совместимости → регрессионные проверки и документация. Код не начинать под видом уже установленной первопричины.
