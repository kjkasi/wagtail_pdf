# План прототипа Wagtail + PDF.js

## 1. Цель

Создать публичный каталог PDF-документов. Для каждого документа редактор Wagtail загружает PDF и задаёт по одному форматированному комментарию на страницу. Посетитель листает PDF двумя кнопками; справа синхронно показывается комментарий текущей страницы.

## 2. Технологическая основа

- Python и Django в версиях, совместимых с выбранной Wagtail LTS.
- Последняя patch-версия наиболее новой **уже выпущенной и поддерживаемой LTS-ветки Wagtail** на дату реализации.
- SQLite для локального прототипа.
- PDF.js (`pdfjs-dist`) с зафиксированной версией.
- Серверная библиотека чтения метаданных PDF (например, `pypdf`) для определения числа страниц и проверки комментариев.
- Обычный JavaScript без отдельного UI-фреймворка.

Перед установкой нужно сверить актуальную LTS и таблицу совместимости по официальному графику Wagtail: https://github.com/wagtail/wagtail/wiki/Release-schedule. Не следует автоматически выбирать объявленную, но ещё не выпущенную ветку.

## 3. Предлагаемая структура контента

### `HomePage`

Главная страница с кратким описанием и ссылкой на каталог.

### `DocumentIndexPage`

Страница каталога. Выводит только опубликованные дочерние страницы документов:

- название;
- краткое описание;
- ссылку «Открыть документ».

### `PdfDocumentPage`

Отдельная страница просмотра документа:

- `title` — стандартный заголовок Wagtail;
- `description` — краткое описание;
- `pdf_document` — ссылка на документ из библиотеки Wagtail;
- дочерние записи `PageComment`.

Ограничить допустимого родителя `DocumentIndexPage`, а допустимый тип дочерних страниц — запретить.

### `PageComment`

Упорядоченная дочерняя модель:

- `page_number` — номер страницы, начиная с 1;
- `comment` — форматированный текст Wagtail;
- связь с `PdfDocumentPage` через `ParentalKey`.

Проверки при сохранении/публикации:

- загружен файл с типом PDF;
- номера страниц положительные и не повторяются;
- номер не превышает фактическое число страниц PDF;
- для каждой страницы PDF существует ровно один комментарий;
- комментарий не пустой.

Если требование «комментарий для каждой страницы» окажется неудобным при первичном заполнении, разрешить сохранение черновика с неполным набором, но блокировать публикацию до устранения ошибок.

## 4. Пользовательский интерфейс

### Каталог

- Заголовок страницы.
- Список опубликованных документов.
- Понятное пустое состояние, если документов пока нет.

### Просмотр документа

На широком экране:

- слева — canvas с текущей страницей PDF;
- справа — заголовок «Комментарий к странице N» и форматированный комментарий;
- снизу — кнопки «Предыдущая страница» и «Следующая страница»;
- рядом можно показать индикатор `N / всего`.

На узком экране блоки располагаются вертикально: PDF, комментарий, навигация.

Состояния интерфейса:

- загрузка PDF;
- ошибка загрузки или повреждённый PDF;
- отсутствие комментария — защитное сообщение, даже если публикационная проверка должна исключать этот случай;
- кнопка «Предыдущая» отключена на первой странице;
- кнопка «Следующая» отключена на последней странице.

## 5. Синхронизация PDF и комментариев

1. Шаблон передаёт URL PDF и безопасный JSON-словарь комментариев по номерам страниц.
2. PDF.js загружает документ с того же домена.
3. JavaScript хранит единственный источник состояния: `currentPage`.
4. Функция перехода проверяет границы, визуализирует нужную страницу в canvas и обновляет комментарий.
5. Обе кнопки вызывают эту функцию с `currentPage - 1` или `currentPage + 1`.
6. Во время рендеринга исключаются параллельные конфликтующие операции; быстрые нажатия не должны показывать страницу и комментарий с разными номерами.
7. Canvas масштабируется с учётом ширины контейнера и `devicePixelRatio`.

Комментарии следует передавать через `json_script` или аналогичный безопасный механизм Django, а не вставлять JSON напрямую в исполняемый JavaScript.

## 6. Этапы реализации

### Этап 1. Инициализация проекта

- Выбрать текущую выпущенную Wagtail LTS и совместимые Python/Django.
- Создать виртуальное окружение и зафиксировать зависимости.
- Создать Wagtail-проект и приложение контента.
- Настроить локальные media/static, локализацию и базовые шаблоны.
- Добавить краткие команды запуска в README.

**Результат:** чистый проект запускается, миграции применяются, админка доступна.

### Этап 2. Модель каталога и документов

- Реализовать `HomePage`, `DocumentIndexPage`, `PdfDocumentPage`, `PageComment`.
- Настроить панели редактирования и выбор PDF из библиотеки документов Wagtail.
- Добавить ограничения дерева страниц.
- Создать и применить миграции.

**Результат:** редактор может создать каталог, документ и постраничные комментарии.

### Этап 3. Валидация PDF и комментариев

- Определять число страниц загруженного PDF на сервере.
- Проверять формат файла, диапазон и уникальность номеров.
- Проверять полноту комментариев перед публикацией.
- Выводить редактору понятные сообщения об ошибках.

**Результат:** нельзя опубликовать документ с некорректной связкой «страница — комментарий».

### Этап 4. Каталог

- Создать шаблон каталога.
- Показывать только live/public документы.
- Добавить пустое состояние и ссылки на страницы просмотра.

**Результат:** публичный пользователь может выбрать опубликованный PDF.

### Этап 5. Интеграция PDF.js

- Подключить зафиксированную версию `pdfjs-dist` и worker локально, без зависимости от внешнего CDN.

- Добавить индикатор загрузки и обработку ошибок.

**Результат:** PDF отображается в собственном минимальном просмотрщике.

### Этап 6. Навигация и комментарии

- Добавить единое состояние текущей страницы.
- Реализовать кнопки перехода и их граничные состояния.
- Синхронно обновлять canvas, номер страницы и комментарий.
- Защититься от гонок при быстрых нажатиях.

**Результат:** комментарий всегда соответствует показанной странице.

### Этап 7. Адаптивность и доступность

**Результат:** прототип пригоден для desktop и mobile и доступен с клавиатуры.

**Результат:** основной сценарий воспроизводимо проверяется автоматически и вручную.

## 7. Минимальная тестовая матрица

### Сервер

- В каталоге видны опубликованные документы и не видны черновики.
- Не-PDF файл отклоняется.
- Повтор номера страницы отклоняется.
- Номер за пределами PDF отклоняется.
- Публикация без комментария хотя бы к одной странице отклоняется.
- Специальные символы в комментарии не ломают JSON или страницу.

### Браузер

- При открытии отображаются первая страница и первый комментарий.
- На первой странице отключена кнопка «Предыдущая».
- «Следующая» показывает страницу 2 и комментарий 2.
- «Предыдущая» возвращает страницу 1 и комментарий 1.
- На последней странице отключена кнопка «Следующая».
- Быстрые повторные нажатия не рассинхронизируют интерфейс.
- Ошибка загрузки PDF показывается пользователю.
- Интерфейс работает на мобильной ширине.

## 8. Критерии готовности прототипа

1. Редактор может загрузить многостраничный PDF и заполнить комментарий для каждой страницы.
2. Некорректный или неполный документ нельзя опубликовать.
3. Опубликованный документ появляется в публичном каталоге.
4. Первая страница PDF открывается без стандартной панели PDF.js.
5. Две кнопки перелистывают документ строго в допустимых границах.
6. После каждого перехода отображается комментарий именно текущей страницы.
7. Страница корректно работает на desktop и mobile.
8. Проект устанавливается и запускается по инструкции из README.
9. Версии Wagtail LTS, Django, Python и PDF.js зафиксированы.

## 9. Что не входит в прототип

- регистрация и авторизация посетителей;
- комментарии посетителей;
- полнотекстовый поиск и поиск внутри PDF;
- миниатюры страниц;
- печать и кнопка скачивания;
- аннотации поверх PDF;
- приватные документы и роли доступа;
- отдельное API или SPA-фреймворк;
- production-инфраструктура и облачное файловое хранилище.

## 10. Риски и решения

- **Большие PDF:** для прототипа рендерить только текущую страницу; лимит размера определить перед production.
- **Несовпадение страниц и комментариев:** серверная проверка перед публикацией и единое клиентское состояние.
- **Повреждённый PDF:** проверка через серверную библиотеку и понятное сообщение PDF.js на клиенте.
- **Обновление PDF после заполнения:** повторно проверять число страниц и блокировать публикацию до исправления комментариев.
- **Будущая смена LTS:** фиксировать версии и обновлять их отдельной задачей, а не использовать плавающие диапазоны зависимостей.
